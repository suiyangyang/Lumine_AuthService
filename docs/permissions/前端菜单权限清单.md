# Lumine AuthServer 前端菜单权限清单

> 状态：Current
> 更新时间：2026-08-05

## 使用建议

- 登录后通过 `GET /api/menus` 读取持久化菜单配置，并结合响应中的 `isEnabled`、`isImplemented` 与 `hasAccess` 构建左侧导航。
- 没有任何后台管理权限的普通用户直接进入“个人中心”，仅显示个人中心导航；拥有后台权限的用户进入仪表盘。
- 推荐将“菜单可见性”和“按钮可操作性”分开判断；菜单通常依赖 `*.view`，写操作按钮依赖 `*.manage`。
- 若接口返回 `403`，可直接读取响应里的 `requiredPermission` 做前端提示。
- 菜单绑定多个权限时采用 OR 语义；没有绑定权限的菜单对所有已登录用户可见。菜单隐藏不替代对应后台 API 的权限检查。

## 菜单与权限映射

| 菜单/页面 | 建议路由 | 可见权限 | 主要操作权限 | 关联接口 |
| --- | --- | --- | --- | --- |
| 个人中心 | `/account/profile` | 已登录 | - | 当前用户资料与账号操作接口 |
| 仪表盘 | `/overview/dashboard` | 后台管理权限 | - | `GET /api/dashboard/summary` |
| 用户管理 | `/identity/users` | `users.view` | `users.manage` | `GET/POST/PUT/DELETE /api/users` |
| 角色管理 | `/identity/roles` | `roles.view` | `roles.manage` | `GET/POST/PUT/DELETE /api/roles` |
| 权限管理 | `/identity/permissions` | `permissions.view` | `permissions.manage` | `GET/POST/PUT/DELETE /api/permissions` |
| 用户组管理 | `/identity/user-groups` | `users.view` | `users.manage` | `GET /api/usergroups`、角色与用户角色接口 |
| OAuth 客户端 | `/auth/clients` | `clients.view` | `clients.manage` | `GET/POST/PUT/DELETE /api/clients` |
| 授权确认 | `/auth/consent` | 已登录 | - | OIDC authorize/consent 接口 |
| Token 管理 | `/auth/tokens` | `clients.view` | `clients.manage` | `GET /api/tokens`、`POST /api/tokens/{id}/revoke` |
| OIDC Discovery | `/auth/oidc` | 已登录 | - | discovery、authorize、token、userinfo 接口 |
| 菜单管理 | `/system/menus` | `permissions.view` | `permissions.manage` | `GET/PUT/POST /api/menus...` |
| 系统配置 | `/system/settings` | 已登录 | - | `GET /api/systemsettings/summary` |
| 审计日志 | `/system/audit` | `clients.view` | `clients.manage` | `GET /api/auditlogs` |

| Knowledge Workspace | `knowledge.maintenance` | 正式同步和运行时索引重建 |

## 前端判断示例

```ts
const configuredMenus = await get('/api/menus');
const visibleMenus = configuredMenus
  .filter(menu => menu.isEnabled && menu.isImplemented && menu.hasAccess)
  .sort((left, right) => left.order - right.order);

const canManageMenus = permissions.includes('permissions.manage');
```
