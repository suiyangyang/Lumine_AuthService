# 权限系统当前状态

> 状态：Current
> 更新时间：2026-08-05
> 适用范围：`Lumine.AuthServer` 与 `Lumine.AuthPortal` 当前已落地的权限模型、接口约束和前端联动

本文档描述当前权限系统的可用状态，不再记录单次改造过程。

## 摘要

- 当前系统采用 `用户 -> 角色 -> 权限` 的三级模型。
- 受保护后台接口通过 `[Permission("module.action")]` 声明访问要求。
- 种子数据已内置用户、角色、权限和默认 OIDC 客户端。
- ReportMind 联调种子包含 `ReportMindUser`、迁移用户、`reportmind.test` 和 `reportmind.reports.upload`。
- Knowledge Workspace MCP 已接入 Lumine API-KEY→JWT→JWKS 鉴权链，并登记 `knowledge.view`、`knowledge.manage`、`knowledge.maintenance`、`knowledge.instruments.view` 和 `knowledge.instruments.manage`。
- 前端导航读取持久化菜单配置，并按菜单启停、实现状态和 `users.*`、`roles.*`、`permissions.*`、`clients.*` 权限实时构建分组与顺序。
- 没有后台管理权限的普通用户登录后直接进入个人中心，仅保留个人中心入口；拥有后台管理权限的用户进入仪表盘。
- 仪表盘统计也会根据当前账号权限裁剪可见数据。
- 第三方服务可以通过当前用户接口读取实时角色/权限，也可以按 Bearer Token 实时检查单个权限。

| --- | --- | --- |
| 用户 | `users.view` | `users.manage` |

| 权限 | `permissions.view` | `permissions.manage` |
| OIDC 客户端 | `clients.view` | `clients.manage` |
| 用户组 | `users.view` | `users.manage` |
| Token 管理 | `clients.view` | `clients.manage` |
| 菜单管理 | `permissions.view` | `permissions.manage` |
| 审计日志 | `clients.view` | `clients.manage` |

这些权限定义来自：

- `Lumine.AuthServer/Infrastructure/Services/AuthSeedOptions.cs`
- 后台接口对应控制器上的 `[Permission(...)]` 特性
- Knowledge Workspace 仪器接口的外部接入映射见 [Knowledge Workspace Service 接入与 MCP 权限设计](../integrations/KnowledgeWorkspaceService接入与MCP权限设计.md)

## 当前覆盖范围

### 后端

- `UsersController`：用户列表、详情、个人信息、状态、密码、角色分配
- `RolesController`：角色列表、详情、增删改、权限分配
- `PermissionsController`：权限列表、详情、增删改
- `ClientsController`：OIDC 客户端列表、详情、增删改
- `UserGroupsController`：基于角色聚合的用户组查询
- `TokensController`：refresh token 列表与撤销
- `MenusController`：后台菜单读取、编辑、排序、重置与权限映射；写操作要求 `permissions.manage`
- `AuditLogsController`：登录、登出、授权码、Token 相关审计视图
- `AuthController`：当前用户访问摘要和第三方实时权限检查

### 前端

- `MainViewModel` 中的导航菜单会使用服务端菜单标题、分组、顺序、启停状态和权限绑定，并根据当前账号访问状态控制显示
- 管理页面的查询和写操作与对应权限编码保持一致
- 无对应权限时，后端统一返回 `403`，并带 `requiredPermission`

## 当前实现结论

| 项目 | 状态 | 说明 |
| --- | --- | --- |
| 权限编码规范 | 已落地 | 使用小写点分风格，如 `users.view` |
| 接口权限声明 | 已落地 | 后台核心资源接口已标注权限 |
| 种子数据同步 | 已落地 | 默认管理员角色与权限在启动时初始化 |
| 知识库 MCP 权限种子与适配 | 已落地 | KWS 接收 Lumine API-KEY 换取 JWT，通过 JWKS 校验并按五项 `knowledge.*` 权限保护工具；管理员种子角色自动获得已配置权限 |
| 前端菜单联动 | 已落地 | 用户、角色、权限、用户组、客户端、Token、菜单、审计日志页面已接入 |
| 菜单配置持久化 | 已落地 | `PortalMenus` 保存可维护字段；内置 Key、路由、图标和实现状态由代码注册保护 |
| 细粒度按钮守卫 | 部分落地 | 主要管理页已接入，后续新增页面需继续同步 |
| 用户组/菜单/审计日志权限 | 已复用现有权限集 | 当前复用 `users.*`、`permissions.*`、`clients.*`，未单独新增权限编码 |
| 审计日志持久化 | 已落地 | 当前新增 `AuditLogEntries` 表，支持认证与授权关键事件查询 |
| 第三方权限复用 | 已落地 | `GET /api/auth/me/permissions` 返回实时权限，`POST /api/auth/check-permission` 支持单权限实时检查 |

## 维护要求

新增或修改权限时，同步检查：

1. `AuthSeedOptions`
2. 控制器上的 `[Permission(...)]`
3. `docs/api/管理后台基础接口说明.md`
4. `docs/permissions/前端菜单权限清单.md`
5. `Lumine.AuthPortal` 中的导航与页面守卫
