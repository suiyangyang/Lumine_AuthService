# Lumine AuthServer 管理后台基础接口说明

> 状态：Current
> 更新时间：2026-08-05
> 适用范围：后台管理 API、登录注册接口和 Swagger 调试

## 初始化数据

SuperDog4.1 生产客户端标识为 `superdog41`，非 PKCE，scope 为 `openid profile roles permissions`。厂家 KEY 创建/查看/复制及逐记录上传接口、DTO 和权限以 [SuperDog4.1 生产接口](../integrations/SuperDog41生产接口.md) 为准；客户端每批开始通过 `GET /api/auth/me/permissions` 复核账号与权限，该调用不刷新 token。

- 启动时会自动执行数据库迁移，并初始化管理员、管理员角色、基础权限、默认 OIDC 客户端和内置后台菜单。菜单配置独立存储在 `PortalMenus` 表中；已有配置会保留，新增的代码注册页面会自动补齐。已有用户的资料以数据库中的当前值为准，启动种子不会覆盖用户在个人中心修改的用户名、邮箱、昵称或手机号。
- 默认种子配置位于 `Lumine.AuthServer/appsettings.json` 的 `SeedData` 节点。
- 默认管理员账号为 `admin`，密码从 `SeedData:AdminPassword` 或环境变量 `SeedData__AdminPassword` 读取。
- ReportMind 用户（包括从 ReportMind 配置迁移的用户）、角色和对应权限由 `SeedData:Users`、`SeedData:Roles` 初始化；`reportmind-test` 密码从 `LUMINE_AUTH_REPORTMIND_USER_PASSWORD` 读取，迁移用户密码从 `LUMINE_AUTH_REPORTMIND_DEFAULT_USER_PASSWORD` 读取。

## Swagger 调试

- 开发环境启动后访问 Swagger UI。
- 先调用 `POST /api/auth/login` 获取 JWT。
- 点击右上角 `Authorize`，输入 `Bearer {token}` 后即可调试受保护接口。
- 每个受保护接口的 Swagger 说明中会显示“所需权限”，并自动标注 `401` / `403` 响应含义。

## 核心接口

管理后台所有分页列表接口当前统一使用以下默认约定：

- 未显式传入 `pageSize` 时，服务端默认按 `50` 条 / 页返回。
- `pageSize` 最大值为 `100`，超过时按 `100` 截断。

### 认证

- `POST /api/auth/login`：使用已注册 OIDC 客户端登录，返回 `access_token`、`id_token`、角色与权限摘要；请求必须提供有效的 `clientId`。
- `POST /api/auth/api-key/token`：第三方使用用户 API-KEY 换取与用户名密码登录一致的 Bearer Token；请求必须同时提供 `apiKey` 和 `clientId`。
- `GET /api/auth/me`：读取当前用户、角色和实时权限集合。
- `GET /api/auth/me/permissions`：供第三方服务读取当前用户的角色与权限集合。
- `POST /api/auth/check-permission`：使用当前 Bearer Token 实时检查一个权限，请求体为 `{ "permissionName": "users.view" }`。
- `POST /api/auth/logout`：记录当前登录用户的登出审计日志。
- `POST /api/auth/register`：注册用户。

登录成功后服务会建立 `lumine-auth-session` Cookie。用户在 AuthPortal 登录后，可继续访问 OIDC 授权端点完成第三方系统登录；API 调用仍应使用返回的 Bearer Token。`clientId` 必须对应已注册且启用的 OIDC 客户端，且请求的 `scope` 必须在客户端允许范围内。

### 仪表盘

- `GET /api/dashboard/summary`：按当前 token 权限返回用户、角色、权限、客户端数量，以及基于成功登录审计记录和 refresh token 的近 7 天趋势、最近登录用户摘要。响应中的 `operationalSignals` 提供以下运营信号：过去 24 小时登录失败、未来 7 天内到期且未撤销的 Refresh Token、启用但缺少 Redirect URI 或允许 Scope 的客户端、过去 24 小时失败审计事件（作为待复核代理）；登录失败信号需要 `users.view` 或 `clients.view`，其余信号需要 `clients.view`。无对应权限时返回不可见标记，不泄露数值。

运营信号的时间窗口均以服务端 UTC 快照时间计算。客户端配置异常按“启用客户端缺少 Redirect URI 或允许 Scope”判定；系统当前没有审计确认状态，因此“需复核审计事件”按失败审计事件展示，不代表已经建立人工确认工作流。

### 用户

- `GET /api/users`：分页查询用户。
- `GET /api/users/{id}`：查询用户详情。
- `GET /api/users/me`：查询当前登录用户。
- `PUT /api/users/me`：修改当前登录用户资料。
- `POST /api/users/me/change-password`：修改当前登录用户密码。
- `GET /api/api-keys`：查询当前用户自己的 API-KEY 元数据和完整 key，个人中心可随时复制。
- `POST /api/api-keys`：创建绑定 `labchrom_knowledge` 的 API-KEY；完整 key 会在创建响应和后续列表查询中返回，个人中心可随时复制。
- `DELETE /api/api-keys/{id}`：删除当前用户自己的 API-KEY，原 key 立即失效。
- `POST /api/users`：创建用户。
- `PUT /api/users/{id}`：修改用户资料。
- `PUT /api/users/{id}/status`：启用或停用用户。
- `POST /api/users/{id}/reset-password`：重置用户密码。
- `DELETE /api/users/{id}`：删除用户。
- `PUT /api/users/{id}/roles`：覆盖用户角色集合。
- `POST /api/users/{id}/roles/{roleId}`：给用户追加单个角色。
- `DELETE /api/users/{id}/roles/{roleId}`：移除用户单个角色。

### 角色

- `GET /api/roles`
- `GET /api/roles/{id}`
- `POST /api/roles`
- `PUT /api/roles/{id}`
- `DELETE /api/roles/{id}`

角色删除会保护系统内置 `Admin` 角色，并拒绝删除仍关联用户的角色；用户组管理页面沿用该角色模型。
- `PUT /api/roles/{id}/permissions`
- `POST /api/roles/{id}/permissions/{permissionId}`
- `DELETE /api/roles/{id}/permissions/{permissionId}`

- `GET /api/permissions/{id}`
- `POST /api/permissions`
- `PUT /api/permissions/{id}`
- `DELETE /api/permissions/{id}`

### OIDC 客户端

- `GET /api/clients`
- `GET /api/clients/{id}`
- `POST /api/clients`
- `PUT /api/clients/{id}`
- `DELETE /api/clients/{id}`

内置第三方客户端包含 `labchrom_knowledge`，用于 API-KEY 换 token。该客户端不使用回调地址，调用方仍需在请求中明确传递 `clientId`。

### API-KEY 管理

API-KEY 管理接口只允许当前登录用户访问自己的 key。创建请求示例：

```json
POST /api/api-keys
Authorization: Bearer {portal_access_token}
Content-Type: application/json

{ "clientId": "labchrom_knowledge" }
```

完整 API-KEY 格式为 `sk-`、6 位随机字符和 32 位无连字符 GUID；数据库保存 `PlainTextKey`、`KeyPrefix`、`KeySuffix` 与 `KeyHash`，以支持后续使用和复制。个人中心列表默认显示 `sk-` 加开头 3 位、`***` 和结尾 3 位，复制按钮使用已保存的完整 key。完整 API-KEY 等同密码，请妥善保管。

第三方换 token 示例：

```json
POST /api/auth/api-key/token
Content-Type: application/json

{
  "apiKey": "sk-xxxxxx...",
  "clientId": "labchrom_knowledge",
  "scope": "openid profile email roles permissions"
}
```

响应字段与 `POST /api/auth/login` 一致，包括 `token`、`access_token`、`token_type`、`expires_in`、`scope`、`id_token` 和用户角色权限摘要。API-KEY 换取的 access token 有效期为 8 小时，且 token audience 使用请求中的 `clientId`。

### 补充管理页面数据接口

- `GET /api/usergroups`：按现有角色聚合生成用户组视图，返回成员数、权限数和成员摘要。
- `GET /api/tokens`：分页查询 refresh token 记录，返回脱敏后的 Token 预览、用户、客户端、Scope、签发时间、到期时间和撤销状态；支持 `keyword`、`status`（`有效`/`已撤销`/`已过期`）和 `expiresBeforeUtc` 筛选。
- `POST /api/tokens/{id}/revoke`：撤销指定 refresh token。
- `GET /api/menus`：登录用户读取后台导航配置，返回标题、分组、顺序、Key、路由、图标、启停状态、权限绑定、当前账号访问状态和页面实现状态。
- `PUT /api/menus/{key}`：修改指定内置菜单的标题、分组、启停状态、说明和权限绑定；Key、路由、图标与实现状态由代码注册，不允许后台改写。
- `PUT /api/menus/order`：使用完整 Key 列表覆盖菜单顺序。
- `POST /api/menus/reset`：恢复全部内置菜单的标题、分组、顺序、启用状态、说明和权限绑定。
- `GET /api/auditlogs`：分页查询已落库的认证与授权审计日志，当前覆盖登录、登出、授权拒绝、授权码签发、Token 换取与撤销；支持 `keyword`、`category`、`action`、`outcome`、`fromUtc` 和 `toUtc` 筛选。
- `GET /api/systemsettings/summary`：返回服务端 OIDC、种子数据和基础统计摘要。

## 权限要求

| 模块 | 查看权限 | 管理权限 |
| --- | --- | --- |
| 用户 | `users.view` | `users.manage` |
| 角色 | `roles.view` | `roles.manage` |
| 权限 | `permissions.view` | `permissions.manage` |
| OIDC 客户端 | `clients.view` | `clients.manage` |
| 用户组视图 | `users.view` | - |
| API-KEY 管理 | 已登录且仅限当前用户自己的 key | - |
| Token 管理 | `clients.view` | `clients.manage` |
| 菜单配置 | 已登录；管理页入口要求 `permissions.view` | `permissions.manage` |
| 审计日志 | `clients.view` | `clients.manage` |

说明：

- `/api/users/me`、`/api/users/me/change-password` 只要求用户已登录。
- `/api/auth/me`、`/api/auth/me/permissions`、`/api/auth/check-permission` 只要求用户已登录。
- `/api/auth/logout` 只要求用户已登录。
- `/api/dashboard/summary` 依赖当前 token 中的权限集合裁剪返回内容。
- `/api/menus` 需要登录但不额外要求查看权限，因为后台壳依赖该响应构建当前账号的导航；修改、排序和重置仍严格要求 `permissions.manage`。
- 菜单绑定多个权限时采用“满足任意一项即可显示”的规则。前端隐藏菜单不替代 API 权限校验。

## 统一响应约定

- 未登录访问受保护接口时，返回统一 `401` JSON：包含 `statusCode`、`error`、`message`、`path`、`timestamp`。
- 已登录但权限不足时，返回统一 `403` JSON，并附带 `requiredPermission` 字段。
- 登录支持历史明文密码兼容；旧账号首次成功登录后会自动升级为哈希密码。
- 如需重置默认管理员密码，可将 `SeedData:ForceUpdateAdminPassword` 临时设为 `true` 后重启服务。
